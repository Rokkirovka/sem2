Команда:
CREATE KEYSPACE demo WITH replication = { 'class': 'SimpleStrategy', 'replication_factor': 3 };

Результат:
cqlsh> CREATE KEYSPACE demo WITH replication = { 'class': 'SimpleStrategy', 'replication_factor': 3 };
cqlsh>

Зачем:
Создаёт пространство ключей (keyspace) с тремя копиями данных для отказоустойчивости.

---

Команда:
USE demo;

Результат:
cqlsh:demo>

Зачем:
Переключается на созданный keyspace для выполнения последующих операций.

Команда:
SELECT * FROM users_by_id WHERE email = 'alice@example.com';

Результат:
InvalidRequest: Error from server: code=2200 [Invalid query] message="Cannot execute this query as it might involve data filtering and thus may have unpredictable performance. If you want to execute this query despite the performance unpredictability, use ALLOW FILTERING"

Зачем:
Пытается выбрать данные по полю email, которое НЕ является partition key. Cassandra блокирует такой запрос, потому что он потребовал бы полного сканирования всех партиций.

---

Команда (в новом терминале):
docker stop cassandra3

Результат:
cassandra3

Зачем:
Останавливает одну ноду кластера для проверки отказоустойчивости.

---

Команда (в cqlsh после остановки ноды):
SELECT * FROM users_by_id WHERE user_id = 123e4567-e89b-12d3-a456-426614174000;

Результат:
 user_id                              | email                 | name  | registered_at
--------------------------------------+-----------------------+-------+---------------------------------
 123e4567-e89b-12d3-a456-426614174000 | alice_new@example.com | Alice | 2026-05-22 09:48:30.501000+0000

(1 rows)

Зачем:
Чтение работает даже при остановленной одной ноде, потому что replication_factor=3 и данные есть на других нодах.

---

Команда (в cqlsh после остановки ноды):
INSERT INTO users_by_id (user_id, name, email, registered_at) VALUES (323e4567-e89b-12d3-a456-426614174002, 'Charlie', 'charlie@example.com', toTimestamp(now()));

Результат:
cqlsh:demo> INSERT INTO users_by_id (user_id, name, email, registered_at) VALUES (323e4567-e89b-12d3-a456-426614174002, 'Charlie', 'charlie@example.com', toTimestamp(now()));
cqlsh:demo>

Зачем:
Запись тоже работает при остановленной одной ноде. Cassandra продолжает принимать записи, а когда нода вернётся в кластер, данные синхронизируются (anti-entropy repair).
