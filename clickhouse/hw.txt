Команда:
CREATE TABLE trips (
    trip_id UInt32,
    start_time DateTime,
    end_time DateTime,
    distance_km Float32,
    city String
) ENGINE = MergeTree()
ORDER BY (start_time, city);

Результат:
Ok.

Зачем:
Создаёт таблицу trips с нужной структурой. ENGINE = MergeTree() — стандартный движок для аналитических запросов. ORDER BY (start_time, city) определяет порядок сортировки: сначала по времени, затем по городу, что ускоряет группировку по городам и фильтрацию по времени.

Команда:
INSERT INTO trips
SELECT
    number AS trip_id,
    toDateTime('2024-01-01 00:00:00') + rand() % 365 * 86400 AS start_time,
    start_time + (rand() % 7200) AS end_time,
    1 + (rand() % 500) / 10 AS distance_km,
    arrayElement(['Moscow', 'Saint Petersburg', 'Kazan', 'Novosibirsk', 'Sochi'], rand() % 5 + 1) AS city
FROM numbers(1000000);

Результат:
Ok. 1000000 rows in set. Elapsed: 0.342 sec. Processed 1.00 million rows, 8.00 MB (2.93 million rows/s., 23.41 MB/s.)

Зачем:
Генерирует и вставляет 1 миллион тестовых строк. numbers(1000000) создаёт временную таблицу с числами от 0 до 999999. Каждое число превращается в случайную поездку: trip_id — само число, start_time — случайный день 2024 года, end_time — start_time плюс до 7200 секунд (2 часа), distance_km — от 1 до 51 км, city — случайный из пяти городов.

Команда:
SELECT
    city,
    avg(distance_km) AS avg_distance,
    count() AS trip_count,
    max(toUInt32(dateDiff('second', start_time, end_time))) AS max_duration_sec
FROM trips
GROUP BY city
ORDER BY city;

Результат:
┌─city─────────────┬───────avg_distance─┬─trip_count─┬─max_duration_sec─┐
│ Kazan            │ 25.982823707871376 │     199333 │             7197 │
│ Moscow           │ 25.750835551463965 │     199868 │             7195 │
│ Novosibirsk      │ 26.044570142380856 │     200668 │             7198 │
│ Saint Petersburg │ 25.916008812325984 │     200347 │             7196 │
│ Sochi            │ 26.117913250698585 │     199784 │             7199 │
└──────────────────┴────────────────────┴────────────┴──────────────────┘

Зачем:
Основной аналитический запрос по заданию. Для каждого города выводит:
- avg_distance — среднюю дистанцию поездки
- trip_count — общее количество поездок
- max_duration_sec — максимальную длительность поездки в секундах (dateDiff считает разницу между start_time и end_time, toUInt32 преобразует в целое число)
